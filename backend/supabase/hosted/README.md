# SQL for the hosted Supabase project

`../migrations/` is the source of truth and runs automatically in local tests. These files are for the **hosted** project only and are pasted into the Supabase SQL editor by hand, in order. Each `NN_apply_*` file is generated by `python -m scripts.prepare_hosted_migrations --first N --last M --output ...` and is safe to re-run: migrations already recorded are skipped.

| File | What it does | When |
|---|---|---|
| `01_inventory.sql` | Read-only list of tables, row counts and migration history | Any time, to check the project |
| `02_drop_legacy.sql` | Drops the four legacy tables that predate the migrations (`restrict`) | Once, after reading 01 |
| `03_apply_0071_0072_hosted.sql` | Tickets and request categories; audit case timeline | Once |
| `04_apply_0073_hosted.sql` | Handover to the RM (`rm_handover` tickets), `handoff_id` in ticket reads, Michelle's deadline 30 Nov 2026 | Once |
| `05_apply_0074_hosted.sql` | Retires the Supabase trace writes (tracing is LangSmith) | Once |
| `06_keep_only_michelle.sql` | Removes every customer except Michelle (1002): their logins and all their rows. Advisers, knowledge and categories stay; the audit log is untouched | Once; run step 1 (preview), then step 2, then step 3 (every count should be 0) |
| `07_catch_up_0068_0078_hosted.sql` | Catch-up. Hosted already had the repository's 0062, 0063, 0065–0067 and 0069 (applied without being recorded); this adds what was missing: 0068 card self-service (made repeatable), 0070 merchant country and login-help article v2 (Alex's rows left out), then 0075–0078 (Michelle's demo charges and pending transfer, bank decisions, statements, reminder clean-up) | Once, after 06. One transaction; safe to re-run |
| `08_apply_0079_hosted.sql` | Clears reminders already in the Inbox that she has acted on or whose deadline is out of date, once now and whenever a due date changes | Once, after 07 |
| `09_apply_0080_hosted.sql` | Michelle can answer the bank's questions on her review (reply box, receipt in Actions, Inbox notice); `compliance.record_request_decision` lets the bank accept an answer or ask a follow-up | Once, after 08 |
| `10_apply_0081_hosted.sql` | Card actions become bank-only: the client can no longer block, unblock or cancel a card or send a dispute draft; reported charges go to the fraud team as an urgent ticket; lost-card, unrecognised-charge and support guidance updated | Once, after 09 |
| `11_apply_0082_hosted.sql` | Code-review follow-ups: a question on a topic that already has an open RM ticket is added to that ticket instead of opening a duplicate; documents selected in the chat can be attached to RM tickets; a lost or stolen card reported by a signed-in client opens an urgent fraud ticket (`card_lost`); Michelle's second card (Travel Card 5592) and sample fees | Once, after 10 |
| `12_apply_0083_hosted.sql` | Cards and loans get a recorded currency (SGD for every demo card and loan), so the assistant says "SGD 316.20" instead of "currency unrecorded" | Once, after 11 |
| `13_apply_0084_hosted.sql` | Michelle's two sample fees get their own names ("Annual card fee", "Telegraphic transfer fee") so fee questions can tell them apart | Once, after 12 |
| `14_apply_0085_hosted.sql` | A different question for the RM in the same chat opens its own ticket (`customer_open_rm_ticket`); approved how-to article for sending money overseas | Once, after 13 |
| `15_apply_0087_0088_hosted.sql` | The general loan article v2 naming car, home and personal loans (CR16; 0086 home and personal loans is already applied); Persona 2 seed (F4): Michelle's adviser record becomes Sophie Lim, two more synthetic clients in Sophie's book and one with Priya, internal `rm.meeting_notes`, `rm.staff_logins`, seven open tickets (rows for David are skipped where he no longer exists) | Once, after 14. Then create the Auth user `demo.sophie@example.com`, set its app_metadata to `{"demobank_role":"rm","rm_id":"00000000-0000-4000-8000-100200000002"}` and re-run the last statement of 0088 to link it |

Never drop a table that `01_inventory.sql` marks "in use": SQL functions and triggers use it even when no Python file names it.

After applying, restart the backend. `DOCUMENT_PRECHECK_SIGNING_KEY` in `backend/.env` must equal `select secret from compliance.precheck_keys where key_id='v1';`.
