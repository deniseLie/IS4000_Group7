# SQL for the hosted Supabase project

`../migrations/` is the source of truth and runs automatically in local tests. These files are for the **hosted** project only and are pasted into the Supabase SQL editor by hand, in order. Each `NN_apply_*` file is generated by `python -m scripts.prepare_hosted_migrations --first N --last M --output ...` and is safe to re-run: migrations already recorded are skipped.

| File | What it does | When |
|---|---|---|
| `01_inventory.sql` | Read-only list of tables, row counts and migration history | Any time, to check the project |
| `02_drop_legacy.sql` | Drops the four legacy tables that predate the migrations (`restrict`) | Once, after reading 01 |
| `03_apply_0071_0072_hosted.sql` | Tickets and request categories; audit case timeline | Once |
| `04_apply_0073_hosted.sql` | Handover to the RM (`rm_handover` tickets), `handoff_id` in ticket reads, Michelle's deadline 30 Nov 2026 | Once |
| `05_apply_0074_hosted.sql` | Retires the Supabase trace writes (tracing is LangSmith) | Once |
| `06_keep_only_michelle.sql` | Removes every customer except Michelle (1002): their logins and all their rows. Advisers, knowledge and categories stay; the audit log is untouched | Once; run step 1 (preview), then step 2, then step 3 (every count should be 0) |

Never drop a table that `01_inventory.sql` marks "in use": SQL functions and triggers use it even when no Python file names it.

After applying, restart the backend. `DOCUMENT_PRECHECK_SIGNING_KEY` in `backend/.env` must equal `select secret from compliance.precheck_keys where key_id='v1';`.
