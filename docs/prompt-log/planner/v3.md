# Planner v3 (2026-10-31)

| Field | Value |
|---|---|
| Prompt | `backend/app/prompts/planner/v3/system.md` |
| Goal | Understand ordinary client intents, multiple requests, corrections and short follow-up replies using relevant conversation context instead of overriding AI classification with broad keyword rules. |
| Model | Configured model through existing LLM gateway and strict `issue_plan` JSON schema. |
| Change | Additional multi-turn disambiguation and explicit separation of request intent from security/permission checks. Uses the latest bounded, redacted conversation history. |
| Expected benefit | Fewer wrong routes for follow-up messages and fewer hardcoded answers for new phrasings. |
| Verification | Offline logic and prompt-file checks; live planner evaluation needed against a representative dataset. |
| Limitations | AI classification is not a security control. Explicit fraud/login/human-routing rules still override it, and fallback rules apply when planner fails on a clear single-domain question. |
