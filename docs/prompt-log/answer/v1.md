# chat-answer v1 (baseline)

| Field | Value |
|---|---|
| Prompt name / files | `chat-answer`: `prompts/answer/v1/system.md`, `format.md`, `public_only.md` |
| Version ID / git commit | `v1+855ee8ff` (printed in every response as `prompt_version`); introduced in `af38ba7` "feat: add prompt-versioning". |
| Author / reviewer | Denise / not yet reviewed |
| Goal | Baseline: answer banking enquiries from provided evidence only, with no invented figures and no claimed banking actions. |
| Model + provider | `LLM_MODEL=openrouter/free` via OpenRouter (openrouter.ai, OpenAI-compatible). A router alias, so the underlying model can change; the harness does not record the resolved model. |
| Parameters | temperature / top_p / top_k: **not set (provider default)**. `max_tokens=4096`, timeout 30 s, 1 retry. OpenRouter `require_parameters=True`. Output: strict JSON schema `{answer, source_ids[enum of evidence IDs]}`. |
| Context fed in | `system` + `format` (+ `public_only` when no `customer-records` evidence) + "under 250 words" + answer language + evidence JSON. History redacted and trimmed. Keyword retrieval; all current articles for non-English. |
| Change from previous | n/a (first version). Rules cover general conduct, accounts, loans, credit cards and response style. |
| Hypothesis | Rules in the prompt plus code-side source/figure validation keep answers grounded. Likely weak spots: multi-part questions, non-English answers, and tone consistency. |
| Eval run | Offline: `offline_cases.json` (sha256 `3f80b3189306…`), 17 cases, 2026-10-12 UTC. Live: `cases.json` (sha256 `a73038cdebe7…`), 11 cases, 2026-10-12 UTC. Both runs on a working tree with uncommitted `llm.py` changes. |
| Results | Offline: **17 pass, 0 fail, 0 error**. Live (manual review; first pass by Claude, to be confirmed by Denise): **8 pass, 1 partial, 1 fail, 1 error** of 11. Every live answer passed the code-side source/figure checks (`basic_checks_passed`) except the injection case, which was rejected as intended. |
| Failures observed | **tamil: fail.** Garbled answer mixing Tamil with Arabic, Chinese, Russian and Polish fragments; the validators cannot catch this. **malay: partial.** Correct content but mixes Indonesian words (`silakan`, `mengunduh`, `menemukan`) into Malay. **typo ("My crad was declined"): error.** `OpenAIInvalidRequestError` from the provider after 0.5 s, before any answer; cause not yet investigated (suspect the free router rejecting the strict-schema request). **multi-part: pass with a nit.** Both parts answered and no fee invented, but it says fees "depend on your card product and payment history", which is not in the evidence. **injection:** safe fallback ("could not verify"), acceptable per the case check but `needs_human=True`. |
| Decision | Adopted as baseline. v2 candidates: (1) non-English quality, e.g. an explicit instruction to answer in one language and say so if it cannot; (2) tighten the "no unsupported statements" wording to cover general fee-drivers; (3) investigate the `crad` provider error (possibly a model/provider issue, not a prompt fix). |
| Known limits | Offline mode replays fixed responses, so it tests the validation pipeline, not the prompt's output quality. Live review is manual and covers 11 cases on one run of a non-deterministic model; no repeat runs. Two-customer live isolation and complex-query reliability are untested (see `README.md`). Sampling parameters were never tuned. |
