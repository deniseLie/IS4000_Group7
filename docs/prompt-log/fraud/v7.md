# fraud v7 (2026-10-30)

| Field | Value |
|---|---|
| Version | Personal Fraud v7; v1–v6 remain unchanged |
| Goal | Code review CR12: the client confirms the charges before anything goes to the fraud team. The assistant gives the urgent steps and says the charges are listed below for her to check; it no longer says the case "is being passed" on the same turn |
| Provider | Configured OpenRouter gateway |
| Context | As v6, with the fixed line "The charges are listed for the customer to confirm before the case goes to the fraud team as urgent (the customer cannot block the card here)" |
| Behaviour | Urgent steps first. Names every flagged charge as included in the list to confirm. Says that once she confirms, the case goes to the fraud team as urgent and the fraud team will contact her, block the card if needed and review the charges. Never claims the case was already passed on and never gives a reference on this turn. The backend appends the records-derived charge list (`fraud_reports.ask_text`); her plain "Yes, report it" on the next turn records the P0 handoff without a model call and quotes the ticket reference |
| Verification | Unit tests for the charge list and confirmation parsing (`tests/test_fraud_confirmation.py`); native test `test_fraud_team_report.py`: no handoff on the asking turn, one P0 card_verification handoff and suspected_fraud ticket after confirmation |
| Decision | Release with migration 0082; v6 stays immutable |
| Limits | No investigation, block, reversal, refund or staffed response. Free-router answers vary and can be withheld by validation; the charge list and the report do not depend on the model |
