# fraud v6 (2026-10-30)

| Field | Value |
|---|---|
| Version | Personal Fraud v6; v1–v5 remain unchanged |
| Goal | Card actions are the bank's: the assistant no longer offers a temporary block or a dispute draft. For charges the customer does not recognise it gives the urgent steps and says the case is passed to the fraud team as urgent |
| Provider | Configured OpenRouter gateway |
| Context | As v5, with the fixed line "The case goes to the fraud team as urgent (the customer cannot block the card here)" instead of the records-derived offers |
| Behaviour | Urgent steps first (official fraud line, report in the official app, freeze in the app if offered). Names every flagged charge as included in the report to the fraud team. Never offers or implies that it or the customer can block, unblock or cancel the card, or dispute a charge. Proposals only identify the reported card and charge for the fraud team's summary. The backend records the P0 handoff and adds the ticket reference |
| Verification | Unit and native tests: no block or dispute offer is proposed, a P0 card_verification handoff and a suspected_fraud ticket are recorded once per reported card, and the reply quotes its TCK reference |
| Decision | Release with migration 0081 (bank-only card actions); v5 stays immutable |
| Limits | No investigation, block, reversal, refund or staffed response. Free-router answers vary and can be withheld by validation |
